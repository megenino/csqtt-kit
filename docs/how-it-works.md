# Как это устроено

[← К описанию](../README.md)

## Общая схема

```
 телефон / компьютер ──(звонок ВК: TURN/RTP)──> основной сервер человека ──> интернет
        │                                        ↑ при сбое — следующий сервер по списку
        │  адреса серверов (зашифрованно), обновления, ссылки на звонки
        └──> технический домен / CDN ──> главный сервер
                                         ├─ панель: список людей (эталон)
                                         ├─ синхронизация запасных, бот, взносы, отчёты
                                         ├─ служба для приложений: адреса, роли, ссылки на звонки
                                         └─ сборка и раздача обновлений приложений
```

## Транспорт (из CSQTT)

Приложение поднимает системный VPN-интерфейс и передаёт трафик через TURN-серверы звонков ВКонтакте: снаружи это
выглядит как зашифрованный медиатрафик обычного звонка. Для этого нужны ссылки на звонки ВК — приложение создаёт их
одной кнопкой (вход в ВК — только на телефоне), следит, чтобы они не простаивали, и заменяет умершие прямо во время
работы. Если оператор режет UDP, подключение само переходит на TCP/TLS.

## Серверы

- **Главный сервер** хранит список людей: администратор добавляет, продлевает, отключает и удаляет людей в его
  панели (или через бота), а синхронизация каждые 2 минуты повторяет это на запасных.
- **Запасные серверы** стоят у разных хостеров и в разных странах. У каждого сервера есть «вес» — насколько охотно
  бот предлагает его новым людям; сервер, через который выход в интернет нежелателен, можно не предлагать вовсе.
- **Основной сервер человека** («прописка»): бот предлагает наименее загруженный из доступных, администратор может
  выбрать другой. В ссылке он первый, дальше — остальные по кругу. Сервер не ответил — приложение переходит на
  следующий, а через несколько часов снова пробует основной.
- **Наблюдение:** замеры нагрузки каждые 5 минут, страница состояния, сообщение администратору при перегрузке,
  сторож на запасном сервере сообщает, если недоступен сам главный.

## Ссылка-приглашение

Первые версии давали ссылку, в которой были адреса и порты серверов. Сейчас ссылка выглядит как
`csqtt://kit?v=3&t=<токен>&d=<технический домен>`:

- адреса серверов приложение получает в **«визитке»** — зашифрованной записи на техническом домене (или через CDN,
  если домен недоступен);
- ключ шифрования и номер визитки вычисляются из токена — без токена визитку не прочитать и не подменить, а сервер,
  который её раздаёт, её содержимого не видит;
- серверы поменялись — визитка обновилась сама, новую ссылку присылать не нужно.

Ссылку удобно пересылать в мессенджерах: она открывается через страницу-приглашение с кнопками «Открыть в
приложении», «Скопировать» и «Скачать приложение».

## Устройства и подпись

- У человека несколько мест под устройства (телефоны и компьютеры вместе). Новое устройство занимает свободное
  место при первом подключении; мест нет — сервер отказывает, а бот предлагает освободить место (отвязать устройство,
  которое дольше всех не было в сети) или попросить администратора добавить.
- Каждое устройство хранит свой ключ (на Android — под защитой Android Keystore, на Windows — средствами системы) и
  подписывает каждый запрос подключения. Сервер узнаёт устройство по открытому ключу и проверяет подпись и время,
  поэтому подставить идентификатор чужого устройства нельзя. Строгий режим не пускает старые версии без подписи.

## Бот

- **Заявки:** человек пишет имя и выбирает срок, администратор одобряет (с взносом, бесплатно, бессрочно или вторым
  администратором) и выбирает сервер; учётка создаётся на всех серверах, человек получает всё нужное.
- **Взносы на хостинг:** бот входит в кабинет хостера того сервера, на котором работает человек, создаёт пополнение
  баланса, присылает QR для оплаты по СБП и проверяет поступление. Деньги идут хостеру напрямую, а не кому-то из
  участников. Не оплачено вовремя — бот предлагает повторить; у администратора всегда есть «подтвердить вручную».
- **Обслуживание:** напоминания о конце срока, продление, места под устройства, лимит трафика (предупреждения),
  сводки нагрузки и трафика администратору.
- **Роли:** у пользователя в приложении только подключения, у администратора — полное меню, включая установку своей
  системы.

## Торренты

Торренты сильно нагружают сервер, а жалобы правообладателей хостеру могут привести к отключению сервера для всех.
Сервер смотрит только на начало пакетов, которые человек отправляет в интернет, и узнаёт признаки торрент-клиента
(поиск пиров, обращения к трекерам, соединения с пирами). Записываются только счётчики по человеку — никаких адресов,
сайтов и содержимого. Дальше действуют правила администратора: предупреждение и решение администратора, взнос на
хостинг или блокировка торрентов (остальной интернет при этом работает).

## Компьютер

Программа для Windows подключается по той же ссылке-приглашению. Сам компьютер в ВК не входит: телефон отдаёт свои
ссылки на звонки на сервер, а компьютер забирает их и подключается к звонку гостем.

## Своя система

Администратор может поставить такую же систему для другой семьи прямо из приложения: указать главный и запасные
серверы и бота — приложение само установит серверы, бота, сторож и создаст учётку администратора.
